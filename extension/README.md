# SaveBridge — תוסף Chrome

תוסף חדש (נבנה מחדש, כי לא נמצא הקוד הקודם). קורא את הפורמטים הזמינים
**מתוך הטאב האמיתי** של יוטיוב — עם העוגיות, ה-PO Token וה-IP האמיתיים שלו —
ושולח לשרת רק קישורים חתומים מוכנים. ראה את ה-README הראשי (`../README.md`,
"שני מסלולי הורדה") להסבר המלא למה זה עובד בלי פרוקסי.

## התקנה (מצב פיתוח / unpacked)

1. `chrome://extensions` → הפעל **מצב מפתח** (Developer mode).
2. **טען תוסף שלא נארז (Load unpacked)** → בחר את התיקייה הזו (`extension/`).
3. פתח את הגדרות התוסף (סמל ⚙️ בפופאפ, או Details → Extension options) וודא
   שכתובת השרת נכונה (`http://127.0.0.1:8723` לברירת מחדל המקומית).
4. הרץ את השרת (`../run-local.sh`), פתח וידאו ביוטיוב, לחץ על אייקון התוסף.

## איך זה עובד

1. לחיצה על "הורד" מזריקה סקריפט לתוך **ה-world הראשי** של דף היוטיוב
   (`background.js` → `extractYouTubeFormats`, דרך `chrome.scripting.executeScript`
   עם `world: "MAIN"`), וקורא את `window.ytInitialPlayerResponse` — בדיוק מה
   שהנגן האמיתי של יוטיוב רואה.
2. מתוך הפורמטים שם, נבחרים רק אלה עם שדה `url` ישיר (לא `signatureCipher`/
   `cipher`) — אלה כבר חתומים ומוכנים לשימוש בלי לפענח שום דבר בצד שלנו.
3. הקישורים הנבחרים (וידאו/אודיו/כתוביות) נשלחים ב-`POST /api/start` תחת
   `resolved`. השרת רק מוריד את הבייטים וממזג עם ffmpeg — בלי yt-dlp, בלי
   PO Token, בלי פרוקסי.
4. אם שום פורמט מתאים לא זמין ללא cipher (קורה לפעמים בפורמטים באיכות
   גבוהה) — נופלים אוטומטית למסלול הישן: שולחים עוגיות + כתובת הדף, והשרת
   מריץ yt-dlp (דורש את הפרוקסי/PO-Token-sidecar המתועדים ב-README הראשי).
5. השלמה: אם ההצפנה כבויה (מצב מקומי, ברירת מחדל) — `chrome.downloads.download`
   ישיר מול `/api/jobs/{id}/file`. אם מופעלת (למצב שרת מרוחק) — מסמך
   offscreen (`offscreen.js`) מפענח את הזרם עם `lib/crypto.js` (תואם בייט-בבייט
   ל-`savebridge_server/crypto_stream.py` — RSA-OAEP-SHA256 עוטף מפתח
   AES-256-GCM, פריימים של עד 1MB) ורק אז שומר בלוב מפוענח.

## מגבלות ידועות (v1)

- **פורמטים מוצפנים (`signatureCipher`)**: לא מפוענחים בצד התוסף — פשוט
  מדולגים. לרוב עדיין נשארים מספיק פורמטים ישירים (במיוחד progressive עד
  720p), אבל לפעמים איכות גבוהה מסוימת לא תהיה זמינה במסלול המהיר ותיפול
  למסלול ה-yt-dlp.
- **בחירת שפת אודיו/כתוביות**: מבוססת על השדות שיוטיוב מחזירה בעמוד; אם
  הסרטון לא מציג כמה שפות שם, לא יהיה מה לבחור.
- **Service worker ותהליך ארוך**: פוֹלינג הסטטוס רץ כל עוד ה-popup פתוח או
  ה-service worker פעיל; אם דפדפן סוגר את ה-worker באמצע הורדה ארוכה מאוד,
  ההורדה בשרת ממשיכה, אבל התוסף לא יעדכן שוב עד שתפתח את הפופאפ מחדש.
- קוד ה-content-extraction לא נבדק מול יוטיוב חי בסביבה הזו (אין גישת רשת
  ליוטיוב מהסביבה שבה זה נבנה) — נבדק ידנית רק שהוא syntactically תקין
  ושה-crypto מתאים בייט-בבייט לשרת (ראה למטה). בדוק בפועל אחרי טעינה.

## מה שכן נבדק

- כל קובצי ה-JS עברו `node --check` (תקינות תחבירית).
- **התאמת ההצפנה נבדקה קצה-לקצה בפועל**: מפתחות נוצרו עם
  `extension/lib/crypto.js` (אותו קוד בדיוק שהתוסף ישתמש בו), מפתח ציבורי
  נשלח ל-`savebridge_server/crypto_stream.py`, שהצפין 2.5MB אקראיים
  (כמה פריימים + זנב לא מיושר), ו-`decryptStreamToBlob` מה-lib פענח אותם
  בחזרה בייט-בבייט נכון. זה מוודא ש-RSA-OAEP ו-AES-256-GCM תואמים בין
  Python (`cryptography`) ל-WebCrypto של הדפדפן.
- מסלול `/api/start` עם `resolved` בלבד (בלי `url`) — יש בדיקת רגרסיה
  ב-`../tests/test_start_endpoint.py` (זה גם מה שתפס באג אמיתי: השרת סירב
  לכל בקשה בלי `url`, לפני שהתוסף הזה נבנה).
